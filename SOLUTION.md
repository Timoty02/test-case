# Решение

## Как запустить

Нужен Python 3.10 или новее, устанавливать ничего не надо.

```bash
python report.py --date 2026-11-10
```

По умолчанию данные берутся из папки `data/` рядом со скриптом. Другую папку можно указать так:

```bash
python report.py --date 2026-11-10 --data path/to/data
```

Тесты:

```bash
python -m unittest -v
```

## Файлы

- `report.py` — программа: чтение и проверка CSV, расчёт на дату, вывод в консоль.
- `test_report.py` — тесты (см. раздел «Тесты»).
- `DECISIONS.md` — принятые решения и допущения.
- `NOTE_FOR_ACCOUNTANT.md` — записка бухгалтеру.

## Тесты

Тесты лежат в `test_report.py` и используют только стандартный `unittest`. Запуск: `python -m unittest -v`. Сейчас их 17, все проходят. Часть тестов работает на реальных данных из `data/`. Остальные собирают маленькие CSV во временной папке, чтобы проверить один случай.

**`RealDataOn1011`: отчёт на 10.11.2026 по реальным данным**
- `test_d1_works`: по каждой работе D-1 сколько выплачено (W-11, W-12, W-14 по 100 000, W-15 15 000, остальные 0), а W-13 на эту дату отменена.
- `test_d1_totals`: итоги D-1. Выплачено 315 000, возвращённый P-2 не входит. В очереди 150 000 (P-4). Осталось 285 000 от суммы договора и 185 000 по работам. Нераспределённого аванса нет.
- `test_d2`: W-23 на 10.11 ещё не принята (приёмка 11.11), а P-8 от 12.11 не учтён. Выплачено 75 000, осталось 15 000, на W-23 приходится 25 000.
- `test_paid_sums_reconcile`: по каждому договору выплаченное по работам плюс нераспределённый аванс в точности равно сумме выплаченных платежей. При разнесении не теряется и не появляется ни копейки.

**`Dates`: восстановление состояния на разные даты**
- `test_refund_window_counts_as_paid`: 05.09 P-2 ещё у подрядчика и считается выплаченным (350 000). 10.09, в день возврата, уже не считается (300 000).
- `test_overpayment_after_p8`: на 12.11 по D-2 выплачено 95 000 при договоре 90 000. Отчёт показывает 5 000 нераспределённого аванса, остаток −5 000 и предупреждение «ПЕРЕПЛАТА».
- `test_before_everything`: на дату раньше всех событий нет ни выплат, ни очереди.
- `test_cancel_after_report_date_is_planned`: на 11.10 W-13 ещё запланирована. Её отменили 12.10, поле `status` в выгрузке это более позднее состояние.

**`Allocation`: правила разнесения платежей**
- `test_done_works_by_completion_date_first`: общий платёж сначала гасит принятые работы по дате приёмки, а не по номеру. Запланированная работа получает деньги последней.
- `test_linked_to_cancelled_goes_to_pool`: платёж, привязанный к отменённой работе, переходит в общие платежи договора и гасит другую работу. В отчёте появляется предупреждение.
- `test_linked_excess_goes_to_pool`: часть привязанного платежа сверх цены работы уходит на следующую работу в очереди.
- `test_kopecks_exact`: 0,10 + 0,20 даёт ровно 0,30 (с float было бы 0,30000000000000004). Остаток равен нулю, копейки разнесены точно.
- `test_queued_linked_shown_on_work`: платёж в очереди, привязанный к работе, показан в колонке «В очереди» этой работы и не входит в «Выплачено».

**`Validation`: ошибки в данных и формат**
- `test_three_decimals_rejected`: сумма с тремя знаками после точки — это ошибка данных.
- `test_work_from_other_contract`: платёж, привязанный к работе из другого договора, — это ошибка данных.
- `test_unknown_contract`: работа, ссылающаяся на несуществующий договор, — это ошибка данных.
- `test_fmt`: суммы выводятся с пробелом между разрядами и запятой перед копейками (`1 234 567,05`), отрицательные со знаком минус.

Тестами не покрыты: текст и вёрстка таблицы в консоли (проверены только глазами) и разбор аргументов командной строки.

## Как устроен расчёт

1. Состояние работ и платежей восстанавливается на дату отчёта по датам (`completed_at`, `cancelled_at`, `created_at`, `paid_at`, `refunded_at`). Поле `status` из выгрузки не используется: оно описывает день выгрузки.
2. Платёж, привязанный к работе, идёт на эту работу. Излишок сверх цены работы и платежи по отменённым работам уходят в общие платежи договора.
3. Общие платежи договора гасят работы по очереди: сначала принятые по дате приёмки, затем запланированные по номеру. То, что не поместилось в цены работ, показывается как нераспределённый аванс.
4. «Осталось оплатить по договору» = сумма договора − выплачено. «Осталось по работам» показано отдельной строкой.

## Что осталось и что можно сделать дальше

- После ответов бухгалтера поправить спорные правила (см. `DECISIONS.md`). Каждое из них — одно место в `build_contract`.
- Добавить выгрузку в CSV, если отчёт будут открывать в таблице.
- Если появятся частичные возвраты, нужно добавить в выгрузку сумму возврата: сейчас возврат считается полным.
